# Judge 제품 정보 확장 (2026-11-14)

## 변경 범위

Spring → judge 응답 대기 기본값: 30,000 → 180,000 ms.
`JUDGE_TIMEOUT_MS` 환경변수로 재정의할 수 있다. 연결/응답 대기에 각각 적용되는
제한이며, 전체 요청의 절대 실행 시간 제한은 아니다. 자동 재시도나 추가 AI 호출은 없다.

기존 `product.type`, `names`, `approvedFunctions`를 유지하고 아래 필드를 추가한다.
`functionSource`는 DB의 PRIMARY_FNCLTY 원문이며, 자르거나 파싱한 값으로 대체하지 않는다.

| 필드 | JSON 타입 | I0030 원본 |
|---|---|---|
| ingredients | 문자열 배열 | RAWMTRL_NM |
| functionSource | 문자열 | PRIMARY_FNCLTY |
| cautions | 문자열 배열 | IFTKN_ATNT_MATR_CN |
| intake | 문자열 | NTK_MTHD |
| otherIngredients | 문자열 배열 | INDIV_RAWMTRL_NM + ETC_RAWMTRL_NM + CAP_RAWMTRL_NM |
| standards | 문자열 | STDR_STND |

원료 목록은 괄호 밖의 쉼표·세미콜론·줄바꿈으로 구분한다. 괄호 안의 복합 원료는
보존한다. 주의사항은 줄바꿈으로만 구분해 쉼표와 번호로 연결된 안전 조건이 분리되지
않게 한다. 단일 주의사항 원문이 배열 원소 하나가 될 수 있다.
각 목록의 항목 앞뒤 공백은 제거한다. otherIngredients는 세 원본 순서대로 병합하고
동일 항목은 중복 제거한다. 원본 7개 항목은 DB에 별도 TEXT로 보존한다.
자료가 없으면 배열은 `[]`, 문자열은 `""`이며 안전·적합을 뜻하지 않는다.
값이 있는 functionSource/intake/standards의 공백과 줄바꿈은 그대로 전송한다.

## 저장·갱신·재검수

`008_judge_product_details.sql`은 기존 자료를 삭제하지 않는 추가 마이그레이션이다.
새 정보만 달라져도 저장하여 제품 version이 갱신된다.
API 필드가 누락되거나 숫자·객체 등 잘못된 타입이면 해당 기존 값은 보존한다.
명시적인 빈 문자열/null은 최신 원본에 값이 없는 것으로 반영한다.
원료/주의사항만 바뀌었다고 기능성 원문 변경 알림을 만들지는 않는다.
기능성 변경 알림의 기존 범위는 유지한다.

검사 결과 `productSnapshot.judgeProduct`에 실제 보낸 제품 객체를 저장하고
`judgeProductSchemaVersion=1`을 기록한다. 재검수 비교는 기존처럼 snapshot 전체를
비교하므로 원료·주의사항·섭취 방법 변경도 동일 기준으로 오인하지 않는다.
옛 검사 결과는 다시 쓰지 않는다. 기능성 추출 실패 시의 기존 검사 보류 조건도 유지한다.

## 적용 순서

1. 백엔드 실행 DB에 008 마이그레이션 적용.
2. 백엔드 재시작. .env의 JUDGE_TIMEOUT_MS가 따로 있다면 180000으로 맞춘다.
3. 식약처 키를 설정한 환경에서 기존 데이터 한 번 전체 보충.
   기존 관리 API는 `FOOD_SAFETY_IMPORT_ENABLED=true`와 ADMIN 인증이 필요하며,
   `POST /api/data/load-all`이 전체 수집을 실행한다. 별도 신규 관리/수동 검토 기능은 없다.
   증분 수집만으로는 이전 제품 전체의 새 항목을 채울 수 없다.
4. 이후 일상적인 갱신은 새 항목도 저장한다. 자동 갱신의 기본 활성화 설정은 변경하지 않는다.

2026-11-14 실제 식약처 키 연결과 46,366건 전체 보충을 완료했다.
API가 값을 제공하지 않은 항목은 빈 값으로 유지한다. 기존 검사 기록은 보존했다.
현재 API 목록에 없는 기존 제품 106개도 삭제하지 않았다. 정기 갱신은 아직 꺼져 있다.

## Judge 담당자 연동

2026-11-14 develop a818d4d를 로컬에 반영했다. 최신 judge의 Product 스키마는
추가 필드 6개를 수신하며 pipeline/fact_check에서 참조한다.
Python 코드는 팀원의 최신 변경을 그대로 사용한다.
실제 식약처 제품 예시를 Product 모델로 검증해 배열/문자열 6개가 원문 그대로 유지됨을 확인했다.
`approvedFunctions`는 기존 호환 필드로 남으며 functionSource 원문을 대신하지 않는다.

프런트 이력에 판정 건수/자료 기준일을 연결하고 완료 결과에서 리포트를 열 수 있게 했다.
현재 검수 생성은 동기 요청이므로 judge 응답까지 POST가 대기한다.
결과 조회 폴링도 180초로 맞췄으나 최초 POST와는 별도 타이머다.
배포 프록시/클라이언트 요청 제한은 180초보다 여유 있게 맞춰야 한다.

최신 judge 테스트 74개가 외부 네트워크 없이 통과했다. 실제 Gemini 키가 없어
최신 판정의 품질·소요 시간·추가 호출 비용은 아직 검증하지 않았다.
## 검증

AI/식약처 호출을 대체한 테스트로 추가 필드 수집, 새 정보만 변경된 제품 저장,
요청 JSON 이름과 타입, 복합 원료·주의사항 보존, 검사 snapshot 저장 및 주의사항 변경 후
재검수 기준 불일치를 확인했다. 실제 외부 API/AI 판정은 실행하지 않았다.
