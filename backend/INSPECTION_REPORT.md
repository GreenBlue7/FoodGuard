# 검수 리포트 보기·인쇄

## 용도와 표시

광고 수정 협의·내부 검토를 위해 검사 한 건의 저장 결과를 공유하는 문서다.
법적 적합 인증서나 식약처 승인서가 아니다.

상단: 문서번호·검사 당시 제품/검사 정보 표·검토 결과 요약.
본문: 번호·대상 문구·판정·검토 의견 및 근거의 4열 검토표.
위반 → 검토 필요 → 문제없음 순으로 모든 항목을 배치한다. 표의 번호는 표시 순서이며 원래 판정 ID를 바꾸지 않는다.
검토 의견 셀에는 저장된 이유·근거·사례·수정 예시를 함께 정리한다.
이후 재검수 비교, 광고 원문, 기능성 원문, 사전점검 안내가 이어진다.
좁은 화면에서는 열을 축소하는 대신 각 항목의 번호·문구·판정·의견을 세로로 펼친다.
끝부분: 검사 당시 기능성 원문과 사전점검 안내.

색과 함께 판정 명칭·건수를 표시한다. 색이 없는 인쇄에서도 구분할 수 있게 한다.
여러 문장을 묶은 지적 하나는 1건이다. HOLD는 검토 필요에 포함한다.
기준일·근거·문장 정보가 없으면 기록 없음을 표시한다. 임의의 날짜·근거를 만들지 않는다.
수정 예시는 재검수 전에는 적합성이 확인된 문구가 아니라는 안내를 붙인다.
재검수의 기록된 기준이 달라졌으면 해소 건수를 확정 표시하지 않는다.
삭제·추정 연결·동일 문장 판정 변경은 구분한다.

## API와 연결

`GET /api/inspections/{jobId}/report`

- JWT 인증 및 본인 소유 기록만 허용. 타인 기록은 404.
- 완료되지 않은 검사: 409. 손상/누락/알 수 없는 판정이 있는 완료 기록: 422.
- 응답은 `text/html; charset=UTF-8`, Cache-Control no-store.
- 기존 결과 JSON/제품 DB를 변경하지 않고 검사 당시 snapshot만 사용한다.
- AI 호출·새 수정 추천·식약처 재조회가 없다.

프런트에서는 인증된 요청으로 HTML을 가져온 뒤 보기/저장을 제공하거나,
별도 확인 페이지 `/reports/{jobId}`로 연결할 수 있다.
이 공개 페이지는 로그인 화면뿐이며 로그인 전에는 광고/제품 내용이 들어 있지 않다.
별도 페이지는 기존 로그인 API와 JWT로 리포트를 받아 미리보기·새 창·HTML 저장을 제공한다.
팀원의 Vue 코드는 변경하지 않았다.

## 형식과 인쇄

첫 버전은 인쇄용 HTML이다. `인쇄 · PDF로 저장` 버튼은 브라우저 인쇄 창을 연다.
사용자가 PDF로 저장할 수 있으며 서버에서 PDF 바이너리를 직접 만드는 기능은 아니다.
A4용 스타일, 반복 표 머리글, 판정별 강조, 페이지 분리 규칙이 포함된다.
브라우저 설정에 따라 머리말·꼬리말·배경색·여백이 달라질 수 있다.
리포트 전체에는 광고 원문이 포함되므로 사용자가 내려받은 파일은 직접 관리한다.

## 안전한 표시

모든 저장 텍스트는 HTML 이스케이프한다. 근거 링크는 http/https만 허용한다.
외부 이미지/폰트/스크립트를 로드하지 않는다.
제한된 CSP와 sandbox 미리보기를 사용한다. 미리보기/새 창의 정적 스타일·인쇄 스크립트만
허용하도록 고정 자산 hash를 허용 목록에 포함한다.

## 검증과 시연

본인 확인, 타인 기록 차단, 미완료/손상 기록 차단, 저장된 과거 정보 표시,
위반 우선순위, 누락 기준일, HTML 삽입/실행 링크 차단, 기준 변경·삭제 비교를 테스트한다.
로컬 시연 결과에는 `demo=true`를 기록하고 문서 맨 위에
`시연 데이터 · 실제 AI 검수 결과가 아닙니다`를 표시한다.

남은 연결: 프런트 결과 화면의 ‘리포트 보기’ 버튼, 실제 judge 결과로 최종 문서 확인.
서버 PDF 직접 생성이나 여러 검사 묶음 다운로드는 이번 범위에 포함하지 않았다.
