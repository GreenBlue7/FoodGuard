# 제품 정보 변경 이메일

## 사용 흐름

1. `/email/settings`에서 본인 계정으로 로그인한다.
2. 주소 확인 메일을 요청한다. 메일의 링크를 열어 `이메일 확인` 버튼을 누른다.
3. 수신 설정 페이지에서 확인 상태를 새로고침한 후 `이메일 알림 켜기`를 누른다.
4. 이후 해당 사용자가 검사했던 제품의 기능성 원문이 변경되면 기존 웹 알림과 함께
   이메일 대기열에 저장한다. 이전 알림은 소급해서 발송하지 않는다.
5. 최소 1분 대기 후 준비된 변경을 한 메일에 묶는다. 1회 최대 100건이며 초과분은 다음 메일로 이어진다.
6. 메일의 `/email/notifications/{id}` 링크에서 로그인하고 현재 광고를 확인한다.
   문구 수정 및 현재 사용 중임을 확인한 뒤 재검수 버튼을 눌러야 AI를 호출한다.

이메일은 기능성 정보 변경 안내이며 위반 확정이나 법정 시정 기한 안내가 아니다.
제품명·신고번호·변경 발견 시각(한국 시각)·확인 링크를 포함하고 고객 광고 원문은 이메일에 넣지 않는다.
이번 변경 이후 식약처 원문 변경 기록은 Asia/Seoul 기준으로 생성한다. 과거 시각은 덮어쓰지 않는다.
별도 HTML 확인 페이지는 백엔드에서 제공한다. 팀원의 Vue 코드는 변경하지 않았다.

## API

JWT 인증 필요. 사용자 ID나 수신 주소를 요청에서 임의로 지정할 수 없다.

| 경로 | 메서드 | 동작 |
|---|---|---|
| /api/notification-email | GET | email, verified, enabled 반환 |
| /api/notification-email | PUT | `{ "enabled": true/false }`; 주소 미확인 시 켜기는 409 |
| /api/notification-email/verification | POST | 본인 가입 이메일에 확인 메일, 성공 202, 재요청 1분 제한 429 |

확인 페이지 GET은 토큰을 소비하지 않는다. 버튼의 POST에서만 30분짜리 일회용 토큰을 소비한다.
토큰 원문은 DB/로그/API 응답에 저장·노출하지 않고 SHA-256만 저장한다.
링크는 fragment에 토큰을 실어 최초 GET URL에 토큰이 들어가지 않게 한다.
메일 앱의 링크 미리보기만으로 수신 동의가 켜지지 않는다.
현재 이메일과 확인 당시 주소가 일치해야 하며, 확인과 수신 동의는 별도 단계다.
발송 기능이 꺼져 있으면 주소 확인 메일 요청은 503이다.

## 저장·발송

`009_notification_email.sql` 적용 후 백엔드를 재시작한다.
notification_email_preferences: 수신 설정, 확인 주소/시각, 확인 토큰 해시/만료/요청 시각.
notification_email_outbox: 웹 알림 ID를 기본키로 하여 동일 알림 중복 적재를 막는다.
제품 갱신·웹 알림·메일 대기열은 동일 DB 트랜잭션에서 저장한다. 저장 과정에 SMTP/AI 호출은 없다.

별도 발송 작업이 1분마다 최대 20개 묶음을 처리한다. 사용자별 발송을 잠그고, 발송 직전에
주소 확인·수신 설정을 재검사한다. 수신을 끄면 대기/처리 중인 메일은 취소하고 웹 알림은 유지한다.
SENT는 SMTP 서버가 수락했다는 뜻이며 도착·읽음 보장이 아니다. 메일을 열어도 웹 알림 읽음 상태는 바꾸지 않는다.

실패 시 1/2/4/8분 간격으로 재시도하여 총 5회 실패하면 FAILED로 보관한다.
발송을 시작한 후 서버가 중단되면 5분의 처리 유예 이후 다시 처리한다.
SMTP 수락 직후 DB 저장 실패나 수락 여부가 불명확한 연결 오류는 중복 발송 가능성이 있다.
SMTP와 DB를 하나의 트랜잭션으로 묶을 수 없으므로 정확히 1회 전달을 보장하지 않는다.
자동 반복/동시 작업에서 이미 SENT인 알림을 다시 보내지는 않는다.
장애 코드만 저장하고 수신자·SMTP 자격증명이 포함될 수 있는 예외 메시지는 저장하지 않는다.

## 설정

기본값은 발송 꺼짐이다.

```
NOTIFICATION_EMAIL_ENABLED=true
MAIL_HOST=localhost
MAIL_PORT=1025
NOTIFICATION_EMAIL_FROM=foodguard@localhost
NOTIFICATION_EMAIL_PUBLIC_API_URL=http://localhost:8080
NOTIFICATION_EMAIL_PUBLIC_WEB_URL=http://127.0.0.1:5173
```

이는 외부로 전달하지 않는 로컬 Mailpit용 설정이다. UI: `http://127.0.0.1:8025`.
로컬 SMTP와 메일함 포트는 127.0.0.1에만 공개한다.

실제 이메일은 운영 SMTP 호스트·포트·MAIL_USERNAME·MAIL_PASSWORD·발신 주소를 설정하고
MAIL_SMTP_AUTH=true, MAIL_STARTTLS=true 및 공개 서비스 URL을 환경에 맞춘다.
SMTP 연결/읽기/쓰기 제한은 각 5초다. 포트 465의 암묵적 TLS는 이 설정에 포함하지 않는다.
서버 외부에서는 localhost 링크가 작동하지 않으므로 운영 URL 설정이 필수다.
운영용 반송/신고 수신 및 차단 정책은 SMTP 제공자 선정 후 추가 연동이 필요하다.

## 로컬 검증과 남은 작업

전체 테스트는 SMTP 발송을 모의 처리한다. 실제 SMTP 연결은 로컬 Mailpit으로 별도 확인한다.
검증: 주소 확인/만료/재사용/재발급/1분 제한, 미확인 수신 차단,
제품 수집에서 대기열 적재, 중복 적재 방지, 비구독자 제외, 묶음 발송,
재시도·최종 실패·작업 중단 복구, 수신 취소, 주소 변경, 타인 광고 접근 차단, AI 추가 호출 없음.

남은 작업: 운영 SMTP 자격증명과 공개 URL 설정, 프런트 메뉴 연결,
정기 데이터 갱신 활성화, 실제 AI 키/판정 서비스 연동 확인.

참고: [Spring Boot 메일](https://docs.spring.io/spring-boot/reference/io/email.html),
[Mailpit Docker](https://mailpit.axllent.org/docs/install/docker/).
